# 02 · 机制

## 一句话

每一关只给你两三个可动的东西，判定用的是**几何**，不是手感。你做的事叫「借」：把不属于园子的东西，框进来。

## 判据表（与 `src/core/geo.ts` 一一对应）

| 关 | 可动 | 判据 | 阈值 |
| --- | --- | --- | --- |
| 1 | 墙头、树 | 山脊整条高过墙头 | 区间内最小间距 ≥ 26 px |
| | | 树挡在山最矮的一段 | 与缺口中心偏差 ≤ 72 px |
| | | 墙要立得住 | 墙头 y ≤ 560 |
| 2 | 左柱、右柱、檐口、雾 | 塔整个落在两柱之间 | 两侧各留 ≥ 24 px |
| | | 塔尖不碰檐口 | ≥ 12 px |
| | | 雾埋住塔脚 | 雾带上沿 ≤ 塔基−24，下沿 ≥ 塔基+12 |
| 3 | 画框、右下角 | 画幅 3:2 | 1.480–1.520 |
| | | 画在纸内 | 完全在画布内 |
| | | 塔在右上三分 | 相对 x 0.58–0.74，y 0.20–0.40 |
| | | 水在下三分 | 相对 y 0.58–0.70 |

## 为什么这么做

- **判据必须是几何的**：这样「看起来对了」和「判过」是同一件事。山脊线同时给渲染和判定用
  （`RIDGE_PTS` 是照着 `public/assets/far-range.webp` 量出来的，页面加 `?ridge=1` 能把这条线画出来比对）。
- **每条判据都要有反例**：`scripts/verify.mjs` 里给每条判据准备了会把它打成 false 的输入（15 条变体），
  否则判据等于没写。
- **可动对象递减**：1 关两个、2 关四个、3 关两个、4 关一个、5 关两个。第 4 关只剩一个，
  是为了让「减法」这件事被身体记住。

## 交互

| 输入 | 行为 |
| --- | --- |
| 鼠标 | 按住可动对象拖；光标按轴向变化 |
| 触摸 | 同一套 pointer 事件；画布 `touch-action: none` |
| 键盘 | 画布聚焦后方向键微调（Shift 加速），`[` `]` 切换对象 |

## 反馈

- 三条判据实时点亮，红点＝已满足。
- 全过才出现「落印」；落印后朱印盖下，2.1 秒进入下一关。
- 「提示」只报当前第一条未满足的判据，不报数字。
- 卡住 75 秒后右下角才出现「跳过本关」——不鼓励跳，但别让评委卡死。

## 不做什么

- 不做失败惩罚、不做计时、不做分数。这不是考试，是看园子。
